## Remaining limitations

- An external writer can still change an existing target in the narrow interval between the final hash recheck and `rename`. Atomic rename plus hash comparison is not a full compare-and-swap operation. A parent directory can also be swapped after path validation by an external process. Create-only saves avoid target overwrite through atomic hard-link creation.
- Corrupt recovery entries remain on disk and are skipped with stderr diagnostics; the current UI does not display those diagnostics. A physically truncated record that is still syntactically valid and below the size limit has no stored length or checksum to detect it.
- Native window-close and dialog behavior was compiled and inspected, but no WKWebView or packaged-app interaction was run here. The optional WDIO feature was compile-checked only. Native UI test status: **NOT RUN**.
